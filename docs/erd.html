관계 정의

관계카디널리티의미
members → send_logs1 : N한 회원에게 여러 번 발송된 기록
members → events1 : N한 회원의 여러 열람·클릭 이벤트
members → member_activity1 : N기간별 Score 스냅샷 이력
newsletters → send_logs1 : N한 캠페인이 여러 수신자에게 발송
newsletters → events1 : N한 캠페인에서 발생한 여러 참여
newsletters ↔ news_itemsN : Nnewsletter_news로 연결 (호마다 여러 뉴스)
news_items → events1 : N뉴스별 클릭 집계 → 인기 콘텐츠 파악
magic_links · admin_sessions—email 문자열로 관리자 식별. members와 FK 없는 별개 인증계

설계 노트

추적 토큰 방식

뉴스 링크를 /r/{token}으로 감싸 클릭 시 이벤트 기록 후 원문으로 302. 열람은 /o/{token} 픽셀. 토큰에 회원·뉴스레터·뉴스를 서명 인코딩해 별도 토큰 테이블이 필요 없음.

Score는 신뢰도 순위 도구

열람(open)은 Apple Mail·Gmail 프록시로 부풀려짐 → 클릭 중심, open은 보조. 정밀 지표가 아니라 상대적 순위로 취급.

program 세그먼트

3,000명이 4개 프로그램(최고책임자·계약학과·사업화·협의회)에 걸침. program + target_filter로 전원이 아닌 세그먼트 단위 발송.

커스터마이즈 범위

세그먼트 단위(활동/비활동 그룹별 다른 뉴스레터)는 현재 구조로 지원. 회원 1:1 개인화는 후속 과제 — 필요 시 per-member 콘텐츠 테이블 추가.

스코어로 필터링

members.current_score·current_state에 최신값을 복제해 두어, "스코어 높은 회원만" 같은 세그먼트 추림이 즉시 가능.

DB 자동 전환

DATABASE_URL이 있으면 PostgreSQL, 없으면 SQLite. 개발은 무설정 SQLite, 운영은 무료 Postgres(Supabase/Neon).
