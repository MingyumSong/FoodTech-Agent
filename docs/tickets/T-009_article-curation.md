# T-009: 기사 선별(큐레이션) 로직 — 파일럿 품질 개선

Status: TODO (2026-07-22 초안 — 파일럿 #0 실발송 관찰에서 도출, 민겸 승인)

## Problem

현재 선별은 "최신순 + 요약 60자 이상"뿐이라 뉴스가치 판단이 없다. 실제 관찰된 증상:
- 톱픽(제목에 노출)에 스타벅스 쿠폰성 기사가 올라옴 (로컬 조립)
- 에피타이저 3건이 전부 "일반" 카테고리 — 분야 다양성 없음
- 메인 카드에 지역지(금강일보) 기사 — **모바일에서 안 열림** (사이트 자체 품질,
  HEAD 404 등 비표준 동작). 독자가 클릭했다 허탕 치면 뉴스레터 신뢰가 깎인다.

## Context (검증된 사실)

- 선별 지점: `app/services/newsletter.py`의 `build_newsletter` — mains/headlines 선정부.
- news_items에 category(11종)·source·region·published_at 있음. 소스명은 네이버 기사에선 빈 값.
- KCL 사례: 같은 내용을 2매체가 보도 — 병합 없이는 코너 2슬롯을 중복이 차지할 수 있음(희정 검수).
- LLM 게이트웨이(OpenRouter, gemini-2.5-flash) 사용 가능 — 분류에 이미 사용 중, 건당 비용 미미.

## Scope

1. **분야 다양성**: 에피타이저 3건은 서로 다른 카테고리 우선 (가능할 때).
2. **소스 신뢰도**: 메인 카드는 주요 매체 우선 — 신뢰 소스 목록(화이트리스트) 또는
   지역지·소규모 매체 감점. 모바일 렌더 불량 사이트를 메인에 올리지 않는 게 목적.
3. **중복 병합**: 제목 유사(예: 자카드/토큰 겹침) 기사는 1건만 — KCL 사례 방지.
4. **뉴스가치 스코어(선택)**: LLM에 후보 N건을 주고 뉴스레터 가치 순위 매기기 —
   분류 크론과 별도로 build 시점 1회 호출. 비용·지연 실측 후 채택 결정.
5. **모바일 템플릿 점검**: 600px 테이블이 모바일에서 어떻게 렌더되는지 스크린샷
   (좁은 뷰포트) 확인 — [[render-visual-output-before-shipping]] 루틴.

## Acceptance Criteria

- [ ] AC1: 에피타이저 3건의 카테고리가 겹치지 않는다 (후보가 충분할 때).
- [ ] AC2: 같은 내용 2매체 기사가 코너에 동시 등장하지 않는다 (테스트로 재현).
- [ ] AC3: 메인 카드 소스가 신뢰 목록 기준을 통과한다.
- [ ] AC4: 조립 결과를 데스크톱+모바일 폭 스크린샷으로 검수한 기록.
- [ ] AC5: check.sh 통과, 기존 발송 멱등·가드 동작 불변.

## Verification

로컬 실데이터 조립 → 스크린샷(800px/390px) → 코너 구성 눈검수 → 운영 build로 재확인.
