# T-017 Activity Score — 참여 점수·등급 산출

Type: FEAT
Status: DONE (2026-08-04 구현·검증·**배포 완료**(커밋 e6468d0) — 08-05 13:00 크론이 첫 실산출)

## Problem

- 현재 동작: 추적(T-003)은 라이브고 `pilot_members`에 발송·열람·클릭 원시 집계가 쌓인다.
  하지만 `activity_score`/`activity_tier`/`score_updated_at` 컬럼은 **T-011 이후로 계속 비어 있다**
  (`refresh_pilot_stats` docstring: "Activity Score는 아직 로직 미구현 — 컬럼은 건드리지 않는다").
- 기대 동작: 회원 1명의 참여 이력이 **0~100 점수 + 등급(active/warm/dormant)** 으로 환산되고,
  발송 잡이 돌 때마다 `pilot_members`에 갱신된다.
- 왜 필요한가: 프로젝트의 핵심 가치가 "추적 → 점수 → 분류"인데 점수·분류가 비어 있다.
  **참여율 높은 회원에게 행사·베네핏을 부여**하려면 그 선별 근거가 있어야 한다(CLAUDE.md 프로젝트 목표).
  로드맵상 다음 항목("Activity Score 로직")이고, 그 다음 관리자 세그먼트 대시보드의 입력이 된다.

## 설계 — 실데이터(파일럿 25명·9회 발송·2026-08-04 기준)로 검증한 공식

### 왜 단순 가중합이 아닌가

결정 5는 "행동별 가중합"이다. 원시 이벤트 수를 그대로 더하면 실데이터에서 세 가지가 깨진다:

1. **열람 수가 부풀어 있다.** 9번 발송받은 회원의 raw open이 22회(프록시·프리페치 재열람).
   반대로 **open이 0인데 클릭이 5회**인 회원도 있다(이미지 차단). 열람 횟수는 순위 재료로 못 쓴다.
   → 열람·클릭을 **편(newsletter)당 1회로 상한**을 걸어 세고, "그 편을 열었나/눌렀나"만 본다.
2. **발송 횟수가 회원마다 다르다.** 25명 중 1명은 발송이 1건뿐(7/21 #906만 수신)인데
   그 1건에서 9개 URL을 눌렀다 — 합산이면 상위권, 비율이면 100점이 된다.
   → **발송 대비 비율** + **축소(shrinkage)** 로 표본이 적은 회원을 중앙으로 끌어당긴다.
3. **오래된 참여와 어제의 참여가 같은 값이 된다.** 활동/비활동 분류는 "지금 살아 있는가"를 묻는 거라
   최근성이 반영돼야 한다. → **반감기 감쇠**.

### 공식

발송된 (회원 × 편) 1건마다 그 편의 참여값 `e`를 하나만 매긴다 (최고 행동 하나, 중복 가산 없음):

| 행동 (그 편에서) | e | 근거 |
| --- | --- | --- |
| 아무 반응 없음(delivered만) | 0 | |
| 열람 | 1 | 프록시 오탐 때문에 최저 가중치 (결정 5) |
| 클릭 | 3 | 의도가 실린 행동 |
| ┗ 같은 편에서 URL 추가 1개당 | +0.5 (최대 +2) | 훑기와 정독을 가른다. 실측 최대 5개/편 |
| 원클릭 반응(T-013 `reacted`) | 5 | 답을 하러 손을 쓴 행동 — 가장 강한 신호 |

`E_MAX = 5` (한 편에서 얻을 수 있는 실질 최대), 반감기 `H = 30일`, 창 `W = 120일`, 축소 `K = 3`.

```
편 가중치   w = 0.5 ** (발송 후 경과일 / H)          # 발송일 기준, 창(120일) 밖은 계산에서 제외
score = 100 × Σ(e × w) / (E_MAX × (Σw + K))
```

- **분모의 `+K`가 축소**다. 발송 3건분의 "무반응 가상 발송"을 늘 깔고 간다 →
  발송 1건뿐인 회원은 만점을 받아도 100×5/(5×(1+3)) = **25점이 상한**. 표본이 쌓이면 영향이 사라진다.
- 점수는 "발송 대비 참여 충실도"이지 절대 활동량이 아니다. **정밀 지표가 아니라 상대적 순위 도구**(결정 5).

### 봇 열람 방어 (결정 11)

실측: 발송 후 **10초 이내 열람이 224건 중 42건(19%)** — 사람이 낼 수 없는 지연이다(스캐너·프리페치).
클릭은 같은 구간이 **0건**(최소 33초)이라 방어가 필요 없다.
→ **발송 후 10초 이내의 `opened`만 무시**한다. 클릭은 그대로 센다.

### 등급 (절대 컷 + 백분위 병기)

| tier | 조건 |
| --- | --- |
| `active` | score ≥ 30 |
| `warm` | 10 ≤ score < 30 |
| `dormant` | score < 10 (창 안에 발송이 있었는데도 반응이 적음) |
| `unknown` | 창(120일) 안에 발송 이력이 0 — 판단 근거 없음. dormant와 구분한다 |
| `unsubscribed` | 수신거부. 점수와 무관하게 분리 |

컷은 절대값으로 고정한다(설명 가능해야 베네핏 부여 근거로 쓸 수 있다). 백분위는 저장하지 않고
관리자 화면에서 조회 시점에 계산해 병기한다 — 컷이 바뀌어도 과거 저장값이 어긋나지 않는다.

현재 25명 적용 결과: active 6 / warm 11 / dormant 8 (분포 0.0 ~ 48.6, 중위 16.9).

## Acceptance Criteria

1. `score_members(...)`가 회원별 `score`(0~100)·`tier`·근거 내역을 반환한다.
2. 열람·클릭은 **편당 1회**로 센다 — 같은 편의 재열람 20회가 점수를 올리지 않는다.
3. 발송 후 10초 이내의 `opened`는 무시된다. 같은 조건의 `clicked`는 정상 반영된다.
4. 발송이 1건뿐인 회원은 그 편에서 만점을 받아도 25점을 넘지 않는다(축소).
5. 최근 발송에 반응한 회원이, 같은 반응량을 오래전에 낸 회원보다 높은 점수를 받는다(감쇠).
6. 창(120일) 안에 발송이 없으면 `unknown`, 수신거부는 `unsubscribed` — dormant와 구분된다.
7. `refresh_pilot_stats` 실행 후 `pilot_members`의 세 컬럼이 채워지고, 연속 2회 실행해도 같은 값이다(멱등).
