# T-027 대시보드 프론트 통합 — 04 Newsletter 섹션을 우리가 채운다

Type: FEAT

전체 구조 그림: https://claude.ai/code/artifact/3be59e9f-7f66-4efb-9c09-bd35c9e43978

## Problem

- **현재 동작:**
  - 관리 화면이 **두 곳에 갈라져 있다.** 희정님 레포(`HeejeongH/foodtech-dashboard`)는 푸드테크
    전반을 다루는 대시보드 프론트를 그려뒀고, 우리는 뉴스레터 관리 화면 5탭을 따로 갖고 있다.
  - 그 대시보드의 **04 Newsletter 섹션은 손으로 적은 스냅샷**이다. 실시간인 건 참여도 TOP 10과
    부제뿐이고, 분야별 클릭 막대·읽은 깊이·발송 검토 팝업은 하드코딩이다.
  - **이미 낡았다**: 대시보드엔 `클릭 92건 중 48건 · 중앙값 11초`, 실제 값은 `36건 · 10초`.
    참여도 순위도 8일 만에 뒤바뀌었다(김슬기 5→3위, 김지우 3→6위, 안병민·곽민재 TOP10 이탈).
- **기대 동작:** 대시보드 프론트를 **우리 레포가 소유**하고 FastAPI가 서빙한다.
  네 섹션 중 04 Newsletter를 우리 5탭으로 채우고, 나머지 셋은 랩실이 이어받을 빈 자리로 남긴다.
- **왜 필요한가:** 데이터의 정본이 우리다(회원 3,422 vs 저쪽 1,463). 화면만 남의 레포에 있으면
  숫자가 계속 갈라진다. 그리고 랩실이 나머지 섹션을 개발할 예정이라 **본보기가 하나 필요하다.**

## 확정된 결정 (2026-08-17)

1. **방향**: 저쪽 프론트를 우리 레포로 가져온다. (반대 방향 — 우리가 API만 주고 저쪽이 그리는 안은
   기각. 마크업이 남의 레포에 남으면 지금처럼 다시 낡는다.)
2. **렌더링**: **JSON API + 클라이언트 렌더.** 지금의 파이썬 f-string HTML 조립을 걷어낸다.
   판단 기준은 "우리가 편한 것"이 아니라 **"이어받는 사람이 읽고 따라 하기 쉬운 것"**이다.
3. **범위**: 우리 5탭(현황·회원관리·인기분야·참여도·발송검토)이 **전부** 04 Newsletter로 들어간다.
   회원 관리도 포함 — 그 탭이 하는 일이 `_recipients`가 고를 **발송 대상 관리**라 뉴스레터 소관이다.
4. **나머지 3섹션**: Overview·Events·Programs는 **Newsletter와 똑같은 모양의 빈 자리**로 남긴다.
   데이터는 붙이지 않는다.
5. **인증**: 안 1 — **페이지 전체를 인증 뒤에 둔다.** 세 안 중 확정(2026-08-17).
   경계가 하나뿐이라 **새 API에 인증을 빼먹는 사고가 구조적으로 불가능하다**는 게 채택 이유다.
   대가로 두 가지가 따라온다:
   - 랩실 사람이 Events 섹션을 만들려면 계정이 있어야 화면이 뜬다
     → **단계 4의 개발 모드가 선택이 아니라 필수**가 된다.
   - 링크를 공유할 때마다 계정을 알려줘야 한다 → **매직링크 로그인이 예상보다 빨리 필요해진다.**

## 후속 — 디자인 이식 정정 (2026-08-17)

**1단계가 디자인을 가져온 게 아니라 다시 지었다.** 화면이 원본과 눈에 띄게 달라서 대조했다.

원인은 원본에 테마가 **두 겹**이라는 걸 놓친 것이다. 전역 `:root` + 범용 컴포넌트(12~335행)와
`.snu-hero-page` 스코프(336~1183행)가 있고 **화면 디자인은 후자**인데, 전자의 토큰만
그것도 값을 바꿔 옮겼다. `snu-` 규칙이 한 줄도 없었다.

실측 차이: 배경 `#0e1535`→`#0b122c`(원본 `--ink-900`을 배경으로 씀) / 패널이 윤곽선만 →
그림자 달린 입체 / 막대 `linear-gradient(#005cb9→#FFD338)` → `#6aaef0` 단색 /
선 퍼플 반투명 → 청회색 / `--accent-purple`·`--accent-coral` **누락** / 14px → 15px + `--mono` 추가.

**고친 방식**: CSS를 원본에서 값 하나 안 고치고 다시 옮기고 **클래스 이름도 원본을 따랐다**
(`.snu-panel`·`.snu-hbar-row`·`.snu-top-presenters`·`.data-table`·`.form-*`·`.status-pill`).
`dashboard.css`를 4부로 나눠 1~3부=원본 그대로, 4부=우리 것만. 원본 결함 하나만 고쳤다:
`#5555888`은 8자리라 무효인 색(→ `#555588`).

### 이름이 겹쳐서 갈아야 했던 것 둘 (안 갈면 조용히 깨진다)

- **`.toast`** — 원본 것은 우하단에 떠서 사라지는 `position:fixed` + `.show`짜리다. 우리 것은
  모달 본문에 남는 배너라 이름을 겹치면 **성공·실패 안내가 통째로 안 보인다.** → `.alert`.
- **`.field`** — 원본 `.snu-popover-body .field`는 `키:값` 표시 행이라 입력에 붙으면 레이아웃이
  뒤집힌다. → `.form-input`/`.form-select`.

### 우리 배치에서 드러난 원본의 이음새 셋 (4부에서 덮음)

1. `.snu-hbar-row .lbl` 100px 고정 — 긴 한글 라벨이 두 줄로 접혔다. 라벨을 짧게 쓰고
   구간 경계는 설명 줄로 옮겼다(원본 스냅샷에서도 접혀 있었다).
2. `.data-table` `width:100%` — `.table-wrap`의 가로 스크롤이 아예 안 걸린다(모바일이 깨지던
   그 원인). 원본 규칙은 두고 `min-width:620px`만 얹었다.
3. **순위 목록이 옆 판보다 커 보였다.** 이름 14px/600 · 행 43px vs 막대 행 13px/400 · 29px.
   원본에선 이 카드가 15px짜리 행사 목록 옆에 있어 맞았지만 우리는 막대 판 셋과 나란히 뒀다.
   → 이름 13px, padding 7px. **색·굵기는 안 건드렸다** — 초점 역할은 유지해야 한다.

### 좌우 균형

등급 칩을 이름 **아래** 줄에 넣어 순위 한 줄이 63px이 됐고, 10줄이면 오른쪽 기둥만
315px 길어졌다(실측). 칩을 이름 옆으로 붙여 43px → 위 3번까지 적용해 37px, 차이 **315→55px**.
패널 넷을 2열로 나누는 모든 조합을 계산했고 95px가 이론상 최소라 현재 배치가 최적이다.

**검수 방법**: 실제 `dashboard.js`를 그대로 불러오고 `fetch`만 가짜로 바꾼 하네스로 렌더해
헤드리스 크롬으로 캡처했다. 마크업을 손으로 옮겨 적으면 실제 화면과 갈라져 검수가 무의미해진다.
크기·높이는 눈대중이 아니라 `getComputedStyle`·`getBoundingClientRect` 값을 DOM에 찍어 읽었다.

회귀: `test_dashboard_assets_are_public_and_load`가 **두 겹이 다 실렸는지** 본다
(`--snu-gold` + `--accent-purple`). 한쪽만 가져오는 게 이번 사고의 원인이었다.
