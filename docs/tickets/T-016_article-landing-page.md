# T-016 중간 착지 페이지 — 진짜 체류 시간 측정

Type: FEAT
Status: TODO (2026-08-01 초안 — 피드백 ③의 완전한 답. T-015 결과를 보고 착수 여부 결정)

## Problem

- 현재 동작: 뉴스레터의 기사 링크는 언론사 원문으로 직행한다. 우리는 "눌렀다"까지만 알고,
  그 뒤 3초를 봤는지 5분을 봤는지 알 수 없다.
- 기대 동작: 기사 링크가 우리 도메인의 요약 카드 페이지를 한 번 거치고, 그 페이지에서
  체류 시간·스크롤 깊이·"원문 보기" 클릭 여부를 정확히 기록한다.
- 왜 필요한가: T-015의 연속 클릭 간격은 근사치이고 마지막 클릭을 못 잰다. 우리 페이지를 거치면
  실측이 된다. **덤으로 파일럿 #0에서 관찰된 "지역지 원문의 모바일 렌더 불량"도 해결된다** —
  요약 카드는 우리가 렌더하므로 어떤 매체든 모바일에서 읽힌다.

## Context

관련 파일·함수:

- `app/services/newsletter_template.py` — `_main_card`/`_headline_item`이 `item["url"]`을 그대로
  href에 넣는다. 여기가 링크 생성 지점.
- `app/services/engagement.py` + `app/routes/webhooks.py` — **여기가 핵심 위험 지점.**
  T-003은 clicked 이벤트의 URL 문자열로 `news_items.url`을 매칭한다. 링크를 우리 리다이렉트로
  바꾸면 웹훅이 실어 보내는 URL이 우리 URL이 되므로 매칭 로직을 함께 고쳐야 한다.
- `app/models/news_item.py` — 착지 페이지가 보여줄 제목·요약·분야·출처.
- `app/models/engagement_event.py` — `event_type` 자유 문자열 + `payload` JSONB
  (체류 이벤트도 여기에 적재 가능할 것으로 보이나, 대용량이라 설계 시 재검토).
- `app/routes/unsubscribe.py` — 토큰 기반 공개 라우트 패턴 참고.

## 착수 전에 답해야 할 질문

1. **이탈 비용**: 클릭이 한 단계 늘면 원문 도달률이 얼마나 떨어지는가? 파일럿에서 A/B로 재야 한다.
   이 값이 크면 지표를 얻고 읽기를 잃는 거래라 티켓 자체를 접는다.
2. **저작권**: 착지 페이지에 실을 수 있는 건 제목 + 짧은 요약 + 출처 + 원문 링크까지다.
   본문 전재는 안 된다. 현재 요약이 어디서 온 값인지(수집 API의 description) 확인하고 인용 범위를 정한다.
3. **T-003 매칭 재설계**: 클릭 URL이 우리 것으로 바뀔 때 기사 역추적을 어떻게 유지할지.
4. **체류 이벤트 볼륨**: heartbeat를 몇 초마다 보낼지, `engagement_events`에 그대로 넣을지 별도 테이블로 뺄지.

2. 원문 도달률이 개편 전 대비 유의미하게 떨어지지 않는다(측정해서 판단).
3. 착지 페이지에 원문 본문을 전재하지 않는다.
