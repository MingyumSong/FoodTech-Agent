# FoodTech Hub — 상세 실행 계획 (8주)

> 2026-07-06 ~ 08-29 · 정례 싱크 매주 목 16:30 · 실제 구현은 1차 싱크(07-09) 이후 착수.

## 설계 원칙 (리서치에서 도출)
1. **클릭이 핵심 신호.** 오픈은 MPP로 오염 → Score·성공지표는 클릭 중심.
2. **도달률은 참여로 좌우.** 도메인 인증 + 워밍업 + 리스트 위생을 발송 전에 준비.
3. **LLM은 보조.** 요약·분류·후보추림까지, 최종 편성은 사람.
4. **빠른 파일럿.** 4주차 소규모 실발송으로 실데이터를 조기 확보해 Score 가중치 확정.
5. **세그먼트 단위.** 3,000명 전원이 아니라 program·활동도 세그먼트로 발송.

## 이슈별 접근 요약 (계획 수준)

**① 이벤트 추적** — 회원별 클릭(주력)·열람(보조)을 `events`에 기록.
- 접근: `/r/{token}` 클릭 리다이렉트(원문 302 전 기록), `/o/{token}` 열람 픽셀(보조), Resend 웹훅(delivered/bounced/complained)
- 핵심 결정: 서명 토큰(DB 행 불필요) · 팬텀 클릭(봇·메일 프리페치) 필터 · 원본 로그 저장 후 집계

**② 크롤링·발송** — API/RSS(사이트가 공개한 기사 목록)로 뉴스 수집 → 주간 발송.
- 접근: 일 수집 / 주간 발송 2단 스케줄. 소스 = 네이버 뉴스 API·언론사 RSS·CrossRef/PubMed. 발송은 배치/백그라운드(동기 루프 폐기) + Resend 배치 API
- **스케줄링:** 플랫폼 크론(GitHub Actions / Supabase pg_cron) 또는 APScheduler. Airflow는 오버킬, n8n은 비주얼/비개발자 편집 니즈 있을 때만. 1차의 background-thread 크론은 교체.
- 핵심 결정: 소스 화이트리스트 확정 · 발송 큐 방식

**③ Score·세그먼트·분류** — 이벤트 → Activity Score → active/dormant → 베네핏 세그먼트.
- 접근: 클릭 중심 가중합 + 시간 감쇠, `member_activity` 스냅샷 + `members.current_score` 복제
- 핵심 결정(A~D): 가중치 · dormant 임계(주 단위) · 웹훅→events 매핑 · 벤치마크 목표치

**④ 관리자 대시보드** — 회원현황·뉴스별 조회·회원별 Score 시각화.
- 접근: 기존 BI(Supabase Interfaces / Metabase) 활용, 자체 개발 X
- 지표: 클릭율·CTOR·구독취소율·리스트 성장률·Activity Score (오픈율 비중 ↓)

**⑤ LLM 파이프라인** — 뉴스 요약·분류·후보 추림 자동화.
- 접근: RSS → 추출 → 구조화 프롬프트 → 저장. human-in-loop(발송 전 사람 승인)
- 핵심 결정: LLM provider(싱크 요청) · 선별 기준 프롬프트 · 비용 상한

1. 🟢 **발송 아키텍처** — `admin_routes.py newsletter_send`에 동기 `for m in members:` 루프 존재. 원작자 주석도 "500명↑이면 백그라운드로"라 명시. 3,000명엔 타임아웃·중복·누락 → 배치/백그라운드 필수(4주).
2. 🔵 **도달률 워밍업** — 신규 도메인 콜드메일은 스팸 처리 위험 → 도메인 인증 조기(2주) + 활동 회원 우선 발송. #1(인증)·#4(동의)에 의존.
3. 🟢🟡 **프로그램 세그먼트** — ✅ **해결(T-002, 2026-07-12)**: 실명단 분석(4,002행 vs 고유 이메일 3,240)으로 다대다 **확인됨** → `member_programs` M:N 테이블로 구현·배포 완료(로컬+Supabase).
4. ⚖️ **수신 동의(법적)** — 정보통신망법상 사전 동의(옵트인) 필수. 코드의 `subscribed`/`unsubscribe`는 옵트아웃이지 옵트인 확보가 아님. 기존 회원 동의 여부 확인 필요.
5. 🟢🔵 **이메일 바운스** — `SendLog.status`에 `bounced`가 정의만 있고 처리 코드·웹훅 없음(코드). 오래된 명단은 바운스 폭증 → 평판 직격(리서치). 발송 전 검증 + 바운스 자동 정리.
6. ⚖️ **개인정보 보안** — 3,000명 PII 보관 = 개인정보보호법 리스크. 접근통제·최소수집·관리자 인증(기존 있음).
7. 🟢 **뉴스 저작권** — 기사 전문·이미지 재배포는 저작권 문제. `newsletter_from_news`가 이미 제목+요약+원문링크 방식이라 안전 구조 유지.
8. 🟡 **운영 지속성(bus factor)** — 8주 후 매주 발송을 누가 지속? 운영 매뉴얼(8주) + 자동화 최대화 + 인수인계.
9. 🟡 **일정 의존성(크리티컬 패스)** — 계정·도메인·실데이터·동의가 싱크에서 안 풀리면 2주차부터 밀림.
   도메인 부분은 ✅ **실행 완료(2026-07-12)**: 학교 DNS를 기다리지 않고 대안대로 `foodtech-center.org` 신규 구입
   → `news.` 서브도메인 Resend 인증(Verified) + 테스트 발송 받은편지함 도착 확인. 남은 의존성: 수신 동의 확인.
