이 프로젝트는 최종적으로 **기관 org로 이관될 예정**이다(규칙 C3). 그때 어려운 건 코드가 아니라
**계정과 시크릿**이다. 코드는 `git`이 알아서 따라가지만 계정은 사람이 옮겨야 하고, 무엇이 어디
있는지 모르면 기억에 의존하게 된다.

⚠️ 표시는 **아직 확인되지 않은 항목**이다. 아는 사람이 채워 넣을 것.

## 시크릿 목록

옮길 때 이 값들을 새 환경에 다시 넣어야 한다. **값 자체는 여기 적지 않는다**(규칙 C6).

- 앱 환경변수 11개 — 목록은 `.env.example` 참조.
  운영 값은 `scripts/railway-env-sync.sh`로 Railway와 맞춘다.
- GitHub Actions 시크릿 4개 — `APP_URL`, `CHECK_EMAIL`, `JOBS_TOKEN`, `RESEND_API_KEY`.
  **레포를 이전할 때 이 값들이 유지되는지 확인되지 않았다.** 이전 전에 목록과 용도를 확보해 둘 것.
- 대시보드 쪽(희정님 Cloudflare Pages)에 우리 `ADMIN_TOKEN`이 `NEWSLETTER_ADMIN_TOKEN`이라는
  이름으로 들어가 있다. ⚠️ **이 토큰은 CSV뿐 아니라 회원 명단과 발송 실행까지 여는 열쇠다.**
  점수 전용 읽기 토큰으로 분리하고 로테이션할 것(T-023 후속).

## 이관할 때의 순서 — 뉴스레터라서 생기는 제약

**이미 발송된 메일의 수신거부·반응 링크가 `PUBLIC_BASE_URL`을 가리킨다.** 지금 그 값은 Railway
주소다. 앱을 옮기면서 그 주소가 죽으면 **과거에 보낸 모든 메일의 수신거부 링크가 깨진다.**
수신거부를 막는 건 법적으로도 문제가 된다.

그래서:

1. 새 환경을 먼저 띄운다.
2. 도메인을 새 환경으로 돌린다.
3. **옛 앱을 한동안 살려둔다** — 링크가 실제로 새 쪽을 향할 때까지.

**지금 대비할 수 있는 것**: `PUBLIC_BASE_URL`을 Railway 주소가 아니라 우리가 통제하는 도메인
(예: `news.foodtech-center.org`)으로 바꿔두면 서버가 어디로 가든 링크가 안 깨진다.
지금은 `admin.`만 도메인에 붙어 있고 발송 링크는 Railway 주소 그대로다.
**단 바꾸는 순간부터 갈리므로**, 기존 메일과의 호환을 생각하면 옛 주소도 계속 살려야 한다.

## 이관 아닌 것 — 랩실 참여

랩실이 Events·Programs 섹션을 개발하는 건 **소유권 이전이 아니라 collaborator 초대**다.
GitHub 레포에 쓰기 권한만 주면 되고, 계정 이전과는 별개다.
다만 인증이 페이지 전체 잠금(T-027 결정 5)이라 **화면을 보려면 계정이 필요하다** —
시크릿 없이 뜨는 개발 모드가 그래서 필요하다(T-027 4단계).
